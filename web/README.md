## 首轮试玩路径

1. 输入道号，选择赠丹、交易或离开，每条都能继续。
2. 返回洞府，自然吐纳至修为满，确认引气入体。
3. 选择剑修或符修，进入历练页前往山野。
4. 采药、凝露；妖核通过战斗、宗门护送或采购取得。
5. 在洞府行囊页炼制筑基丹，或在坊市采购成丹。
6. 修为圆满后确认突破，实际消耗筑基丹；缺材料或修为时不能突破。

也可先做宗门杂务挣灵石，完全不战斗地购买成丹。这是测试路线示例，不是强制顺序。按钮成本和禁用理由来自同一规则预览；批次只结算实际执行的行动。

## 目标、来源与批量行动

当前目标默认跟随下一突破；可替换为物资、功法、法宝或已出现的仙缘。点击缺口查看获得方式，再展开配方/采购所需资源，可逐层返回。来源显示确定产出、准备/行动成本与真实限制；斗法物资明确以胜利为前提，战损另计。追踪材料不被锁定，用药/出售/炼制影响追踪库存时显示轻量提示。

“前往”只提交旅行并定位相关按钮，同行囊/商店里的采购、炼制或挑战分别确认，不自动结算整条来源路线。已在此地的查看操作不写游戏档。按钮为不可达地点显示真实原因。

修炼和采集/委托支持1、5、20、50次或达到目标。物资目标来自来源链中的目标库存，仍按每次固定产出结算，单批最多50次；灵石按缺口规划当前可完成的有界委托批次。修为满、资源不足、目标已齐或寿限等由同一引擎停止。预览区分预算上限和当前预计扣费；实际结算显示请求/执行次数、毛扣费、净变化及停止原因。最大预算不是启动条件，不为未执行步骤扣费。

追踪选择只保存为当前浏览器、当前人生的显示偏好，不进Game或消耗游戏月；刷新保留，换人生恢复默认目标。不支持偏好存储时可继续游戏，游戏存档状态与偏好提示分开。本地试玩记录与显示偏好使用独立数据区，不混入Game；详见下节。

## 本地试玩记录、显示设置与导出

设置中的100/150/200%文字大小和降低动效会保存在当前浏览器。游戏进度与显示设置的保存提示分开：设置失败会明确仅本页生效，不把它写成存档失败；存储未知或不可读时使用默认显示设置并停止采集，原数据不自动覆盖。当前追踪目标仍按人生隔离，换人生恢复默认目标。

欢迎页与设置明确告知默认仅在本机收集必要行为。可以关闭采集、查看最近本地记录或清空记录；清空有页面确认，只影响试玩记录，保留Game和显示设置。最多保留最近1000条、约1MB有效记录载荷，超出时移除较早记录并显示计数。记录故障可退为明确的本页临时记录，退出/刷新可能丢失，不能将它称为已经持久保存。

导出先预览数量与范围，再点击“下载记录文件（JSON）”。文件包含必要行为/数值摘要、指令与人生/版本标识、相对会话时间和当前显示/追踪快照，不含道号、完整存档、错误原文、设备指纹或自由输入。没有上传接口，下载后由测试者自行决定是否分享。文件不是Game存档，不能用于恢复；完整进度请用独立的存档导出。

会话毫秒是观察时刻（包含阅读），不推进游戏年月，也不触发收益或自动突破。当前规则没有随机seed，字段明确为null；回执重放不是再次行动，原行动时间未知。关闭网页不会记作失败。导出说明采集关闭/故障/截断与本页临时数据的边界，不保证是一份完整行为史。清空/关闭采集挡住旧排队数据，预览和下载都核对清空epoch及设置revision。

性能检查使用生产预览4177，端口须空闲：`npm run test:performance`。固定Chromium、10Mbps/150ms、冷context/禁缓存，四尺寸4倍CPU及1440的1倍参考，30样本检查原3秒/200ms/2.5MB/15MB目标；实际硬件、源码/运行包hash与结果在performance-report/measurements.json，不能外推成公网/CDN/真机保证。夹具为正常网页操作生成的后期存档，复制前等待Game及本地记录队列完成；这些自动化数据不是真人试玩反馈。

## 战斗与事件

观察敌方意图，选择攻击、护体、术法、终结术法、补给或撤退。剑修积累剑意，符修积累符印；具体效果和费用以当前规则与装备为准。失败后保留已有功法与物品，可返回洞府疗养。

修行页的功法与法宝面板显示当前三个功法槽和一个法宝槽。功法在青云宗研习，再逐槽装备；金丹后在洞府炼制法宝，再装备生效。显示后续境界可提前看真实限制和筹备来源，实际操作仍由同一规则校验。切换修法会采用该派基础组合，研习和法宝记录保留，可重新装备已有功法；战斗/未决事件期间不能借配装绕过当前状态。开场和普通人物事件分别显示实际选项；导入非破庙事件也可刷新、选择并继续。

## 筑基后的筹备

筑基后可从古境采玉或宗门勘脉取得地脉灵玉，再炼制凝金丹；也可用委托收入在坊市采购成丹。两种修法都能使用两条筹备路线，突破仍须修为与物品齐备。

功法替换的收益来自真实效果：例如止水剑心/太清符心会改变静修，听雨剑势/寒霜符改变战斗行为；研习本身不会自动装备。法宝炼成后也须装备，替换不会销毁其他已拥有法宝。消耗影响追踪或所选配方的材料时会提示，但不预留资源。

## 高境筹备信息

筑基以后，修行页的“本境筹备”独立于当前置顶目标：即使仍追踪已学功法，也能看到本境突破物和配方最高阶材料。材料的确定来源、宗门替代和采购均来自共享查询，显示库存、真实费用与条件；前往只旅行并定位实际操作。突破物已经备齐时，不再要求重复收集该配方。

金丹的月华莲、元婴的凝魂晶、化神的道蕴砂均有当前境界可达的确定路线与替代。归来后可按完整配方制作或购买成丹，修为满后再突破；新境信息和存档中的境界记录随实际状态更新。正常至化神验证没有启动渡劫，后者由后续任务单独验收。

## 存档与恢复

每条游戏指令经过commandId/runId/expectedRevision校验，IndexedDB事务完成后才发布角色状态和“已保存”。存储失败会显示“本次未保存”，重读旧进度不会假装成功；可重试错误使用同一原意图，避免重复结算。

设置中可导入、导出、恢复完整准备检查点或重新开始。恢复会产生新runId、同步回退资源/历史，检查点仍可再次使用。旧M1/Adventure与已知full旧版经过校验转换，保留数据库原记录；坏档或未来版本不会覆盖好档。不明数据库可通过“导出原件备份”保存原始资料，该格式用于恢复调查，不是直接可玩的Game存档。

多标签页通过已提交进度提示同步，实际写入仍依靠事务校验。不同地址、端口和浏览器不共享存档，可导出/导入迁移。清理浏览器数据可能丢档，建议自行备份；没有云同步或反作弊承诺。

## 问心、三关与续行（T14）

问心回望真实开场和已选人物记录，不补写未曾发生的恩情；两种应对的效果和战斗结算共用定义，没有隐藏道德必败。三关进度、当前选定机制和完成状态可读，气血、灵力、丹药、剑意/符印与敌方意图来自当前已保存进度。刷新/暂离继续同一回合，不重抽或自动打完；普通攻击、护体、补给仍由玩家选择。

本轮刚结束时，页面用同一人生相邻的上一提交显示真实战斗阶段和手记原因。仅有匹配的已验证入场快照才显示本轮累计耗物；导入或缺失快照不会伪造累计数。可保留当前状态重新筹备，也可核对目标后完整恢复；确认期间其他页面推进须重新核对。配额失败不部分回退，取消只丢弃这一次恢复的重试，成功后检查点仍可再次使用。当前Game导出不携带独立检查点，说明已在页面显示。详见[问心与三关记录](../docs/implementation/goal-1-trial-journey.md)。


## 飞升封卷与完整正常路线（T15）

三关完成后，可选择留道传承或独赴上界，两者都是飞升成功。先核对当前来路，再确认保存；取消/Escape不改变进度。确认期间其他页面推进或换人生，需要重新核对；保存失败保持三关完成状态和原准备检查点，可重试同一次封卷。成功后显示实际生平、封卷行囊与已记录人物选择，不补写未发生的故人、援助或上界寿元，也不继续上界玩法。可导出、恢复已有完整准备或明确开启新人生。

欢迎页或行旅设置可打开“演示节点”。9个节点从正式newGame/advance回放生成，演示页面有持续标记和返回正常游戏入口。演示的进度、追踪、显示设置及本地记录与正常游戏分离；每个演示运行版本/节点独立继续，重载只替换本节点的演示进度。正常存档的资源与境界不因查看或进入演示而变化。

演示导出使用专用封装；只能导回当前候选/节点，正常导入拒绝。直接访问未知/错误/旧版本节点时不会打开正常档。渡劫准备节点载入时没有伪造检查点，实际确认入场才保存完整准备，后续恢复仍遵守原子协议。

生成文件在web/public/demo-nodes与web/.generated，均由构建/开发入口自动生成且不入Git。候选zip解包后执行`python3 serve.py`，使用本机HTTP地址；源码通过`source.bundle`恢复，按根README锁定安装和重建。原始报告、版本、SHA与已知限制随包保留，外部交付回执证明实际包测试和干净重建，不把装配成功或演示跳转当成正常通关/真人认可。

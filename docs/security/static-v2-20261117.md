# 独立可玩页静态安全扫描与修复

用户要求使用web-zip-security-scanner扫描并根据结果修复。来源基线为640b30b，目标为`web/public`完整静态目录，附查`web/index.html`与`web/vite.config.ts`；没有将源码、测试工具或历史资料当作ZIP交付，也没有扫描默认排除的依赖、Git元数据、dist/build等目录。

## 扫描结果与修复

初扫18处动态innerHTML写入为High；关联Vite源码入口另有1处站点根路径，共19处High。玩家名及日志来自可修改的localStorage，原页中污染存档并打开人物详情可实际触发脚本；不将此复现扩大为无需本地存档污染的远程漏洞。

所有18处动态HTML写入接入实际DOMPurify清洗，玩家名和日志额外作文本编码。清洗策略保留所需HTML/SVG和data-*交互属性，禁止活跃嵌入、事件、表单、跳转、外部图片源及危险样式；只允许游戏内已存在且MIME受限的内嵌栅格图片。原有游戏函数只增加显示安全包装，未改变费用、成长、奖励、战斗或存档数据格式。

使用[DOMPurify 3.4.18](https://github.com/cure53/DOMPurify/releases/tag/3.4.18)原版分发文件，参考[上游配置说明](https://github.com/cure53/DOMPurify#can-i-configure-dompurify)。来源、npm包SHA-512、实际文件SHA-256及许可在[第三方记录](../third-party/dompurify.json)；没有伪造同名清洗函数。清洗库使用包内相对路径，缺少或不支持时显示错误并禁止开始，不继续渲染存档。原有升级说明已更正为需要完整vendor目录的离线静态包。

源码入口改为`./src/main.ts`。Vite的`base:'./'`原已合规，保持不变；新生成的独立复验产物引用`./assets/...`，构建产物静态扫描0项。源静态目录、关联入口/配置与独立交付包最终复扫均为0项。

- 13项定向Node测试：规则解析、嵌套模板/分号、清洗调用边界、绝对路径、协议/标签、Data URI、私网/IPv6、Vite配置、UTF-8警告、默认排除、库完整性，以及ZIP实际内容和拒绝覆盖。
- 固定1440×900 Chromium中，原版污染存档脚本实际执行；修复后相同玩家名/日志保持文字，10类恶意事件/协议/文档/外部资源/样式载荷被移除，无页面错误或外部请求。
- 正常新人生、五个页签、SVG图标、图片、真实修为增长、刷新承接，以及正常破境/法则/剑修/灵兽/星图/斗法通过。战斗可能实际一招获胜，按真实保存的胜场核对，不强行要求胜利后仍保留战斗面板。
- 缺库时停止启动并显示原因；同一Chromium的HTTP子目录和直接file打开通过。此为本次静态包路径修复的定向复验，不代表恢复跨浏览器、移动端、字号或环境性能矩阵。
- 根TypeScript检查通过；Vite直接编译704模块通过，其新产物路径复扫0项。没有冒称完整核心、完整UI/Native/正常32或真人/长期平衡通过。

证据保存在`artifacts/security-v2-20261117/`，包括初始报告、原始HTML、首次语法/测试失败、复核报告、正常截图和最终浏览器报告。首轮扩大玩法验证曾把已真实获胜误判成必须仍留在战斗，已改为核对原始战局及真实胜场增量；没有为断言改游戏。

## 交付与后续边界

`python3 scripts/package-static-v2.py <新目录>`生成独立可用的静态目录及同名ZIP，包含index.html、本地清洗库/映射/许可、README和逐文件hash清单，无包内后端或CDN前提；拒绝覆盖旧产物。生成包与原文件逐字核对、ZIP CRC与静态复扫通过。

本扫描不校验外部脚本URL、不进行DNS或远程资源抓取；为实施修复单独取得并核验了固定版本的官方库。独立JS默认只参加路径检查，清洗库用上游身份和浏览器载荷验证补充，不称通用JS源码审计或完整渗透测试。

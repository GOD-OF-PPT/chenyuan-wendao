# 0160：Q13 App 按业务职责拆分

2026-11-13。依据0149和综合评审第13项、工程报告§3.1，承接Q12/PR56。只重构职责与类型接线，不改变规则、周期、预算、原子保存、离开累计、操作路径、文字、绘画与既有CSS层。以下为实施合同，尚未完成。

## 当前缺口与边界

当前App.vue约166KB，同时承担里程碑意图与四组dialog、活动分发、传输/重开/恢复、舞台导航/焦点、帮助/设置、错误呈现和只读查看器。已有Store与规则层保持原保存权；新重构不能为了减少App行数而另造Store、生命周期或巨型context转发包。约30KB是职责拆出后的目标尺度，不建立新字节帽，也不以删功能/压缩格式达成。

采用codebase-design技能的Module/Interface/Seam思路：先找真实可单独读懂和验证的职责，再将内部状态、条件、异常和回调聚拢；外部Interface保少量明确动作/数据。类型必须来自真实合同，不能用any/动态变量查找、eval、通用模板编译或任意字符串事件总线替代接线。

## 顺序与交付

1. **里程碑确认组。** 收拢收卷、正式入劫、完整准备恢复、飞升收卷四组dialog与其intent、stale、确认/重试/关闭逻辑；其它通用milestone/configuration原Interface继续保。公开的是明确request入口和必要阶段回调，内部持有原意图/原人物修订与原dialog。不能把已提交丢回复刷新成新授权，不得扩大重试范围或重复成果。
2. **四类玩法内容。** 修行、历练、行囊、仙缘模板与相应本地只读状态按当前实际使用链拆，保DOM顺序、原data-testid、KeepAlive身份/上限、分页与主次层级。复用原对象Module，不再多包一层仅透传所有App变量的壳；要实际减少调用方须了解的内部细节。
3. **按剩余职责继续拆。** 存档传输/控制、舞台导航/返回上下文、只读查看与活动启动等内部逻辑在各自Module维护。App负责组合和跨职责交接；原App/Store权属不可散到多个奖励时钟或写者。格式化抽出的可读代码，不改SVG、文章或历史证明，Q14完整死代码/历史守卫改革另验。

保持显示和玩法等值；必要的纯结构修正必须列明同点证据。事件、ref、样式scoped归属与document查询会受组件边界影响，不能仅凭Vue编译通过声称行为等值。明确验证provide/inject的所有权、dialog焦点监听注册/释放、卸载后旧异步回调惰性、跨页/同run新修订与import/restore/newlife隔离。

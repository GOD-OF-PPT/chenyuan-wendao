## 问题判断

当前主要问题是信息结构。一个界面常同时展示玩法目录、所选对象、详细规则、预算表单、预估停止、当前活动、旧成果、下一步和完整导航。它们各自有标题、边框和高亮，玩家需要先理解一个管理界面才能决定做什么。侧栏和正文重复人物状态/活动/停止原因；修炼、炼丹、交易、研习又过多共用“参数—预估—提交”的组织方式。去掉几层边框改善不了这种负担。

本次回读Riot《Clarity in League》（2021-03-12）的重要程度对应表现强度、控制视觉噪声原则，以及Xbox XAG109关于随时查看当前目标/前置进度、细分明确下一步的要求。来源分别为https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/ 与 https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/109 。以下布局与数量是本项目设计选择，不是上述资料规定的行业数值，也不是对竞品的完整试玩结论。

## 三层信息，保持一屏入口

1. 常驻层只保留紧凑人物状态、一个当前目标、一个当前活动以及八个主入口：修行、历练、丹炉、功法、法宝、行囊、仙缘、生平。帮助/设置和目标详情有固定入口。导出放在人物/设置内，仍可达。场景作为主体，不把三个信息栏围在中央工作台四周。
2. 决策层只显示所选对象、用途、下一次/本段明确费用、有限目标与一个主要行动。默认页面不展开高级数字输入，不同时突出“继续、重排、开始、查看下一步”等多个同级主动作。查看/预选即时且不执行；真实开始必须保留完整有限授权摘要。
3. 详情层按需打开单一侧页/对话页：全部目录、预算和保留量、配装比较、完整回执、历史、全部目标。一次只开一个详情表面，不叠加多个抽屉。长目录分页，返回恢复原对象/草案。所有原能力、条目、成本和结果仍可查，不能把“减负”变成删功能。

一个“当前活动条”跨页保持名称、当轮读秒、已完成量及暂停；不同页不再复制同一份完整累计账本。普通完成反馈落在对象附近，保留简短成果入口；预算到限、缺物、危险和关键选择才突出。旧回执不得触发新奖励效果。执行与编辑草案分离，切页/打开设置不擅自暂停或变更活动，确认扩大授权沿用原CAS和保存边界。

## 各界面各有自己的交互

| 界面 | 默认画面与主要决定 | 按需打开 |
| --- | --- | --- |
| 修行 | 洞府与静修人物；当前修炼方式、真实修为目标；开始/暂停 | 灵石辅助、有限次数/累计预算、突破完整准备 |
| 丹炉 | 当前丹方、炉、药匣及下一炉投入；开炉/暂停 | 全丹谱、炉次/目标库存、预算/保留、耗材来源 |
| 历练 | 地点与资源点；先选目的地/对象，再明确行旅或安排采集 | 全地图/委托、战策优先级/用药/风险与回执 |
| 功法 | 所选玉简及真实作用；研习已选内容 | 全流派目录/有限研习清单、已掌握与装入比较 |
| 法宝 | 当前器物与本命槽位；炼制或比较后装备 | 全器谱、实际材料/累计上限、完整机制 |
| 行囊 | 紧凑数量格；选一物后才展示说明与用途 | 出售安排、来源/配方、后续物资与分页 |
| 仙缘 | 当前人物与对话；拜访后显示当前可选回应 | 人物名册、来路/因果说明及选项详情 |
| 生平 | 一页可读手记；章节切换/翻页 | 完整年月/战报、导出、检查点/收卷确认 |

待安排时主按钮是明确游戏动词；运行时主控制是暂停。已达标时显示阶段成果与下一步，不把失效按钮、旧行动摘要和新建议排成一片。缺物时按钮说“查看凝气草来源”，不能在查看过程中暗中旅行/购买。

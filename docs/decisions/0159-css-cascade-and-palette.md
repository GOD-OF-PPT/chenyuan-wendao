## 分阶段完成同一Q12

1. **先固定层叠，不改视觉。** 在任何色值收敛之前，建立显式样式层，完整清点入口CSS、组件style与实际编译结果。不能只包全局而留下同等竞争的scoped样式在层外，导致普通优先级翻转；不能把现有important草率拆到多个顺序相反的层。允许先将相互竞争的现有作者样式放在同一明确层，保原选择器、顺序、属性、重要性和动画。import/font/keyframes等按实际语法处理，不做失效嵌套。
2. **再收敛语义调色。** 以约12个角色token组织青黛背景、物件/交互层、正文/辅助、玉色行动、旧金进度、危险与影色；透明度和渐变由这些角色派生。现有主题/显示选项继续成立，同一角色可有主题值，不能为凑12个颜色删主题或把SVG绘画色当界面token。去除零散近似色和无用fallback，实际字面量/token覆盖给出一致口径数据。
3. **限制后续升级。** 新样式不加important或#app竞争；保留必须的旧声明并让变更可读，不为字节帽压成单行。新增颜色进入角色token，不再逐功能发明相近hex。检查应验证真实样式/行为，不能恢复整文件hash、逆变换或源码字节帽。

层叠阶段要求同一已提交Game、同浏览器/字体/1440×900、同原时钟与帧点的基线图及实际计算样式无意外变化。调色阶段允许明确记录的颜色统一，但不得借此改变布局、字形尺寸、可见性、状态识别、命中或关闭功能。两阶段证据分开，不能用后者有意色差掩盖前者的层叠回归。

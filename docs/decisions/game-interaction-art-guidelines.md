# 《尘缘问道》游戏交互与美术开发准则

调研与制定：2026-10-20（Asia/Shanghai）。来源是下列实际查阅的一手页面；规则中的单屏、配色、命令、读秒与工程数值是本项目已有决定，不能伪称外部行业统一要求。根AGENTS.md是开发执行入口。本文不代表用户已认可当前游戏，也不将无障碍专项等同认证。

## 来源与适用范围

| ID | 一手来源 | 本项目采用的原则 |
| --- | --- | --- |
| S1 | Riot Games，[Clarity in League](https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/)（2021-03-12） | 视觉让玩法容易辨认；重要性决定注意力，控制噪声；形象与实际机制一致，在不同环境核对可辨认度。应用于主次动作、敌意/招式和效果层级，不照搬竞技游戏规则。 |
| S2 | Microsoft，[XAG109 Objective clarity](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/109) | 玩家随时可回看目标、前置进度与明确下一步，能复看已有剧情。应用于境界缺口、材料来源和连续行动，避免靠记忆找入口。 |
| S3 | Microsoft，[XAG116 Time limits](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/116) | 非核心玩法的文字/提示需要足够阅读时间，可由玩家推进。应用于持久结果与手动翻阅；它没有要求每个动作等待，动作耗时是用户明确决定。读秒不转化为限时阅读或限时通关。 |
| S4 | Microsoft，[XAG101 Text display](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) | 实际HUD、说明和菜单文字必须可读，考虑大小、间距及用户调整。保留本项目字号和缩放门槛，不能用缩字塞满面板。 |
| S5 | Microsoft，[XAG102 Contrast](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102) | 在实际背景、控件与提示场景检验可辨认度，颜色之外还需形状/文字。应用于山水上的正文底板、焦点、禁用和错误。 |
| S6 | [Game Accessibility Guidelines：Full list](https://gameaccessibilityguidelines.com/full-list/) | 控制简明、互动教学、情境帮助、目标提醒、文字由玩家推进、控件稳定可达。只采用适合当前有限文字修仙游戏的部分，不增加已否定玩法。 |

## 可执行规则与验收

| 规则 | 开发要求 | 必须提供的证据 |
| --- | --- | --- |
| G01 游戏舞台 | 场景/人物/当前动作建立主视觉；功能切换保留身份、状态和目标上下文。统一青黛墨绿、玉色操作、旧金边/关键进度。避免多层同等强调的卡片和重复标题；插画有明确场景或操作职责。 | 正常开场、修炼、取材、炼制、配装、事件、战斗、渡劫、结尾的整屏实拍；不能只交孤立插画。 |
| G02 一屏与完整信息 | 常用桌面主入口、当前决策、返回和翻页无需滚动。正文/配方/记录完整分类翻页；不裁切、不用嵌套长滚动或缩字掩盖空间不足。 | 实际高度/宽度、文本边界、按钮命中与所有目录项遍历，包含长文和保存/失败状态。 |
| G03 明确下一步 | 展示“目标—当前缺口—可达来源—下一步”。查看/选择/追踪与实际旅行、采购、挑战分清；不让满修为玩家继续无效吐纳。提示入口必须通向真实可执行步骤。 | 新档实走择法、筑基炼制/采购两路，逐次核对Game与引擎；查看全Game不变。 |
| G04 动作合同 | 真正行动前就近说明动作、消耗、效果、资格/禁用原因；主动作突出，次要入口降低强调。图标有文字，不靠悬停或颜色传达必要信息。 | 实际普通/选中/按下/禁用/焦点/错误画面与真实费用，不用写死演示数字。 |
| G05 六阶段反馈 | 输入即给按下反馈；受理后显示动作名/总耗时/递减读秒；截止后显示保存中；提交完成后才显示真实成功/变化；失败给原因与原意图重试。 | 保存前Game不变、真实倒计时递减、持锁事务到期仍无成功、失败/重试/过期和换人生测试。 |
| G06 持续结果 | 短光效结束后仍能读到主要实际变化和下一步，完整成本/停止原因可打开复看。摘要可选最重要的少量条目，必须标明其余变化并可查看；不要把短暂toast当唯一结果。 | 等光效结束后的可见结果/完整回执；刷新、重放、只读切页和外部新进度不虚报新收益。 |
| G07 表现层级 | 修炼/取材/交易/丹火/学习/配装/战斗/破境各有可辨反馈；普通动作克制，关键突破与天劫才用较强表现。效果不挡按钮、不抢焦点、不制造假伤害、掉落或隐藏概率。 | 真回执绑定、actual delta对照、最多粒子/原时长预算、减少动效后的静态结果与命中检查。 |
| G08 美术身份 | 场景、人物、敌方、天门阶段与真实Game对应；功能主题图仅作装饰，不冒充库存/装备。生产图无烘焙文字/数值/按钮，有来源、原稿、提示词、回执、alpha与导出hash。 | 当前ID→实际文件→真实页面使用链，完整解码、坏图/迟到回调、旧图留存与原资源预算。 |
| G09 可读性 | 沿用现有正文18px、辅助信息至少14px、关键目标≥44px及既有对比/缩放/焦点门槛。实际半透明/hover/disabled背景上测量；画作与正文分安全区。 | DOM字体/对比/几何和截图并行；不将WebKit当Safari真机。全部兼容按用户优先级末段处理，缺口不能删。 |
| G10 流程可恢复 | 每境的修炼、关键物确定/替代获取、制作/购买、突破、恢复都能连续操作；普通突破真实消耗修为与物品。没有援助也可主线推进；零资源有合法恢复，失败不能锁死下一步。 | 正常新档、真实指令和全状态对照；不得靠导入节点/加物过关。核心卡点优先于装饰深化。 |
| G11 时间边界 | 保留现有25类动作0.6—2.4秒等时长表；批量用已说明的整批时长。查看、翻页、预览即时；阅读/离线不推进游戏月。无现实时间奖励、五分钟筑基或限时通关条件。 | 时钟边界、卸载/刷新/后台/过期、重复提交测试；虚拟时钟路线与真实墙钟读秒分别记。 |
| G12 完成证据 | 需求、已实现功能、自动化通过、远端提交、候选包、用户验收分开。全矩阵每格记录执行版本、结果和缺口责任；取消/失败后的未执行项不算通过。 | 当前全部声明与原始报告逐项闭合；原完整UI/IDB/72正常/60恢复/30性能门禁保留，真实试玩意见优先。 |

每次修改选择适用规则，先复现卡点，再做小闭环，最后核对这些规则与实际画面。每三个任务综合检查；整体完成仍依Goal1计划和真实用户复验，不以规则文档或机器绿灯代替。

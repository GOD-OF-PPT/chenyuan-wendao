## 研究时的基线问题（U2-I实施前）

当时正式[Action](../../src/full/types.ts)有25类。[Store.write](../../web/src/store.ts)先等表现时钟，再一次提交命令；[时长表](../../web/src/action-timing.ts)固定短耗时，修炼/采集批次没有逐周期等待；[引擎](../../src/full/engine.ts)可在一次指令中同步结算整批。[存档仓库](../../web/src/full-persistence.ts)有可靠的原子保存与回执，但尚无持久活动、活动目标、暂停/恢复或自动战策。原子保存正确与可放置玩法完整是两个不同结论。

因此，需要改变玩家与游戏之间的分工：玩家选择修行安排、资源投入和战策，游戏持续执行已授权的小行动；玩家回来查看进展、处理变化、调整方向。反复打开目录、选择数量、点击执行、看成功回执，再到下一页重复，仍然是软件流程。只换国风皮肤、收起按钮、延长等待或自动快速走完全部境界，都不能解决这一问题。

## 所有玩法共用的交互合同

1. **每个玩法均有可放置方案。** 改变Game的小行动必须归入可重复活动、限次安排或条件触发策略之一；不能只给修炼加循环。有限动作可预先安排，到点自行完成一次；不必为了“可放置”把已经学会、拥有或完成的内容无限重复。查看、阅读、追踪和配置即时响应，不加假进度。
2. **一次安排，持续执行。** 玩家先选目标/方式，再以可理解的默认方案开始；默认方案本身必须显示并落实适用的有限费用/用药/次数或目标上限及安全停止边界，预算、保留库存等细项可进一步调整。累计实际支出不能被同期收入抵消或自动重置，扩大授权上限需要玩家明确确认。每个周期自动保存并开始下一周期，不要求周期结束再次点击执行或逐条领取。初版一个持续成长活动，切换必须清楚显示原活动如何停止；并行能力以后另定。
3. **等待期间有可规划的取舍。** 每个玩法须说明“为何选它、投入什么、能改善哪条后续活动、何时回来调整”。效率、材料、货币、功法、法宝与风险至少形成实际可验证的取舍；不要只添加一个没有其他决策的长计时条。深度先来自已有资源/流派/敌意与配方联系，不凭文档新增一套未获认可的随机品质或经营系统。
4. **活动可辨认。** 常驻活动区用游戏语言显示所做之事、目标进度、下一周期读秒、真实预算/消耗及暂停入口。查看其他玩法时仍知道什么正在运行；不长时间用全局busy封锁页面。主舞台一个主决策，低频参数按需展开；完整入口、返回与单屏原则保持。
5. **每个玩法有自己的操作与反馈。** 炼丹围绕配方/材料/炉火与成丹，采集围绕地点/目标资源/行路，功法围绕流派/作用/搭配，斗法围绕敌方/出招/战策。共享开始、暂停、继续的基础操作，但不能把所有页面做成相同表单、审批卡和成功弹窗。表现绑定真实阶段与回执，文字/数值/按钮由DOM渲染。
6. **结果自然累积，重要变化才打断。** 普通周期更新累计净变化、完成量与短反馈，保留完整成本/记录，不弹重复领取、确认或大成功横幅。阶段完成、资源不足、危险和待决定有清晰持久提示；红点只指向可处理的新变化，不能给受限/无效动作持续催促。突破/天劫可用更强演出，但不能挡住暂停与选择。
7. **停止条件是玩法的一部分。** 支持按目标数量、预算、保留量、完成次数、修为上限、危险阈值停止；已学会/已拥有/无变化时停止，不持续空转或收费。说明达标数量可能以完整周期为单位，并给出真实停止原因。资源不足不自动买、卖或换活动，除非该后续动作已被明确安排。
8. **自动执行保留玩家意图。** 战斗按预设的招式优先级、敌方意图、药物预算与撤退规则运行，手动干预可选。因果选择、问心、择法、突破和收卷可在玩家选定内容并确认代价后安排执行；未选定的关键分支停为“待决定”，不擅自随机替选、自动归隐或连跳境界。
9. **费用与成长真实。** 计划预览分别说明本周期和整个计划的成本/收益，预估与已保存进度分开；奖励只来自已完成的合法周期。普通突破仍检查修为和物品。数值保持未平衡标记，不规定几分钟通关，也不把不合理等待或不可达成本当长期养成。
10. **计时与结算共同受规则管理。** 活动记录必须带身份、周期、计划/完成量、稳定周期命令、状态和停止原因；奖励、扣费、回执与下一活动状态同事务保存。暂停、保存失败、重试、刷新、换人生和其他页面接管均有确定边界。一次迟到回调不自动兑换多周期；后台/离线结算需独立合同，不能靠显示层时钟猜测。

## 25类正式行动的放置与交互改造矩阵

下表是全玩法开发合同：`CULTIVATE` 已由U2-I实施在线周期修炼，`SOURCE` 已由U3接入周期采集/委托，`CRAFT`/`FORGE` 已由U4接入逐炉炼丹/一次炼器，其余21类仍**待实施**。已有按钮、短读秒、预算与原子回执不等于活动机制已实现。每行的“安排”代表游戏内可直接操作的交互，具体实现状态以上述记录为准，不是交给玩家手写脚本或填写工作台表单。

| Action | 玩法与玩家安排 | 可放置执行与有意义的取舍 | 专属反馈与停止边界 |
| --- | --- | --- | --- |
| `CULTIVATE` | 修炼：选择自然/灵石辅助、修为目标与灵石保留量 | 逐周期积累；修为效率与赚灵石/取材时间有机会成本，功法改变实际效率 | 吐纳气息、修为增长和周期环；满修为/预算不足/寿元边界停止，不自动破境 |
| `SOURCE` | 采集/委托：选择地点、资源或灵石目标、执行次数上限 | 自动重复当前来源；安全取材、委托收益与战斗来源有不同代价，目标达成即结束 | 行旅/采集或委托进度、实际物资包；达标/寿元/无产出/地点失效停，不默许旅行或改来源 |
| `CRAFT` | 炼丹：选配方、成丹数量与保留材料 | 炉火逐炉完成；在恢复丹与突破丹、现有库存和后续需求间取舍 | 炉火阶段与真实成丹累计；缺材/预算/成品目标停，不反复点击领丹 |
| `FORGE` | 炼器：选一件未拥有的法宝与投入上限 | 限次铸造完成一件；先炼何物取决于流派和材料用途，不凭空增加重复品质洗炼 | 器纹/炉火与真实法宝完成；已拥有/缺材料停，不无限重复收费 |
| `LEARN` | 研习：选择未掌握功法及可负担的先后顺序 | 按已安排项目逐一研习；展示对修炼或斗法的实际作用，学会后停止该项 | 经卷/术式与掌握进度；已学会/不足/条件变更停，下一项不越预算 |
| `STUDY` | 参悟剑简：选择既有剑简与明确一次费用 | 有限参悟后自行完成，说明剑/符实际受益差异，不造无用途的循环 | 剑简意象与真实效果；已研读即止，不再次收费 |
| `SCHOOL` | 择法：预先选择剑/符及其基础搭配 | 一次安排生效；更换需由玩家明确选择，不能自动替玩家轮换流派 | 流派演示与基础配装确认；相同修法不重复执行，重大变化提示其影响 |
| `EQUIP` | 功法装配：选择目标槽位/预设与生效时点 | 空闲时即时或在已选活动边界自动应用一次，不能在周期中途悄改收益 | 槽位与实际作用前后对照；未学会/流派不合/已装备停，不加虚假长计时 |
| `EQUIP_RELIC` | 法宝装配：选择已拥有法宝及生效时点 | 按玩家预设应用一次，明确影响修炼还是战斗，避免每次战斗重新装配 | 本命法宝与真实效果变化；未拥有/已装备停，不重复消费 |
| `BUY` | 补给：预选物品、库存目标、数量与总灵石上限 | 符合库存条件时按计划采购，预算保护突破筹备；不是无上限扫货 | 货物入囊、实际花费与库存；目标/资金/位置/资格不符停，不隐式旅行 |
| `SELL` | 出售：预选可出售物及保留库存 | 条件触发出售多余物资，保留配方/恢复所需量；禁止随意清空 | 物品流转与灵石净入；保留线/禁售物/位置不符停，不自动卖突破物 |
| `USE` | 服丹：预选丹药、恢复阈值与用量上限 | 达到条件后使用一次或按既定恢复策略运行；预算与继续历练风险有取舍 | 角色回元与真实库存扣除；已满/药尽/预算耗尽停，不空耗丹药 |
| `REST` | 疗养：安排恢复至可继续行动或圆满 | 恢复自动结束；返回洞府、耗用游戏时间与使用丹药分清 | 洞府疗养与真实恢复状态；圆满/寿元/地点失效停，不治疗后反复耗月 |
| `TRAVEL` | 行旅：明确选择目的地或确认计划中的行路段 | 自动抵达一次；到达后的活动只有预先安排才启动，选地点预览不会旅行 | 路径/行路进度/到达场景；已到/条件失效/计划取消停，不暗中跑图 |
| `ENCOUNTER` | 历练目标：选敌方、场次/掉落目标与补给/撤退边界 | 按预设进入挑战并衔接已选战策；再次遭遇须满足安全与场次预算 | 敌方出现、当前目标与战前风险；补给不足/危险/目标达成/待决定停 |
| `BATTLE` | 自动斗法：设招式优先级、意图应对、服丹与撤退条件 | 合法逐回合执行，剑修蓄势/终结与符修护持/印记/引爆需有实际差异；允许主动干预 | 敌意、招式、双方变化与持久战报；胜败/撤退/危险/药物上限停，胜利才结真实战利品 |
| `EVENT` | 拜访机缘：选已开放人物/事件与行程 | 在当前合法地点安排一次拜访；移动位置须有明确安排的TRAVEL，单独EVENT不隐含旅行；不刷同一剧情 | 人物/场景/来由与因果作用；已完成或遇未预选分支停为待决定 |
| `CHOOSE` | 开场抉择：玩家先选赠丹/交易/保留 | 已选择后可安排自动完成一次；展示关键代价，未选时安心阅读 | 人物回应与实际因果/物品变化；结算后停止，不倒计时代选 |
| `DECIDE` | 机缘回应：预选当前可见选项 | 该选项按既定计划执行一次；条件变化停下重看，不自动换成其他选项 | 关系/事件回应与真实因果记录；已决定/条件不符停，不重复发奖励 |
| `BREAKTHROUGH` | 破境：确认本次目标境界、费用与计划边界 | 可安排本境准备齐后自动执行一次；不得串联全境界，不能跳过物品与修为条件 | 凝神/破境演出及真实境界变化；缺物/不足/已完成/状态变化停 |
| `START_TRIAL` | 渡劫入场：确认渡劫引、恢复与本次战策 | 安排入场一次，可接已预选的问心与斗法策略；未知选择等待玩家 | 登台/检查点与实际耗物；未备齐/已入劫停，不重复耗引或自动重开 |
| `ANSWER_TRIAL` | 问心：玩家预选当前答案 | 已选答案自动执行一次并进入对应阶段；未选不催读、不替选 | 因果回响与问心回应；已答/问题变化停，接续依赖已授权战策 |
| `END` | 飞升收卷：玩家选定既有结尾 | 一次明确确认后自动收卷；正文/结果可以稍后回看，无须逐段点领取 | 天门/归卷与完整生平；已结束即止，不默认挑选结局 |
| `RETIRE` | 归隐：明确选定主动收卷 | 限次安排一次，确认后自动完成；不是挂机资源不足后的默认恢复方式 | 归隐场景与生平保留；未确认不执行，不自动结束人生 |
| `END_LIFE` | 寿尽收卷：当前满足寿尽条件后明确安排 | 一次确认后按合法费用完成；持续活动先在寿元边界停，不能由现实等待直接授予死亡 | 寿元边界/归卷与实际记录；条件未到或未确认停止，不后台擅自耗尽寿元 |

新建人生、保存、导入/导出和恢复检查点属于控制操作，不是可刷收益的小玩法；它们保持明确的人类意图与原子结果，不能由活动自动重置或替换用户存档。完整玩法能力保留，一屏主入口不等于把25个执行按钮全部常驻。

## 一个贯穿交互的本项目例子

目标为筑基丹，玩家选择先准备凝气草。现有配置中采药每次获得2凝气草；若库存2、目标8，计划显示还需6、预计3个完整周期。玩家选择采药后可离开此功能页查看功法、比较灵石辅助与继续赚取灵石的收益；游戏自动逐周期积累，达到8停止并保留实际累计。丹炉会展示已齐/仍缺的材料与炼制安排入口，玩家可改走采购路线。这里的目标数量与产出来自现有内容；周期秒数尚待活动参数确定，不能把例子冒称当前已实现。

要验收的体验是“安排→自动进展→回来发现阶段变化→作下一次取舍”。玩家不需每次采药确认、每次保存确认或每一炉点击领取；有意义的决定仍留给玩家。换活动、保留物资、改变流派和提高自动战策效率应改变实际结果，不能只让流程按钮从灰色依次变绿。

## 游戏画面与反馈规则

主舞台围绕角色所处场景与当前活动构图，青黛/墨绿为底、玉色强调当前可操作项、旧金标示关键进度。活动阶段有稳定位置，不因累计结果不断插卡把暂停/返回挤走；场景中的炉火、气息、行旅和招式服务真实活动，普通周期克制，重大变化突出。长物资、功法、战报与故事用完整分类/翻页呈现，不缩字、截断或增加页面滚动。

进入每个玩法时先看懂“做什么、为何做、投入与产出、何时停”，默认提供可理解的安排。预算/保留量等细项按需展开，不能要求玩家先填一长串字段。详情、暂停、重试与切换使用清楚的动词；“查看来源”和“开始行旅/采购”分开。技术术语commandId、revision、事务或兼容诊断不进入玩家流程。

具体操作以玩法对象为中心：洞府由明确的修炼入口选择吐纳方式，山野选择资源点与目标物，丹炉选择已有配方/药匣并看到材料投入，功法/法宝从当前槽位查看替换与实际作用，斗法从敌方意图与战策入口调整攻守。主按钮使用“开始吐纳”“采集至目标”“连续炼丹”“按此战策历练”等实际动词。可点对象必须有可辨的DOM按钮/文字和按下反馈，配合场景构图；图片未加载时仍可操作，不靠玩家猜测装饰画的热点，也不把拖拽或悬停当成唯一入口。

读秒只表示活动/动作进度，不是阅读时限。周期结束真实结果自然出现；需要处理的异常保留原因与同意图重试，普通收益不遮挡场景。不同玩法必须有对应的场景反馈和操作重点，仅更换标题/插画但保留相同软件表单不算完成逐玩法交互。

## 工程落地与实施顺序

共享活动状态由规则/持久层拥有，表现层不能决定奖励。当前`createActionClock`是≤2400ms的表现截止器，不能直接当长期活动时钟；需要独立的、可测试的活动协调与持久记录。可考虑在现有状态库保存独立活动记录，避免把计时器对象塞入Game；最终结构与数据库版本策略在实施项确定，不在本研究中擅自迁移用户档。

周期必须以稳定commandId、runId、expectedRevision及活动归属/版本校验，通过同一事务更新Game、前一状态、回执、完成周期和下次活动状态。失败停止推进，重试核对同周期；暂停立即失效本地回调并以数据库结果确定提交边界。刷新、后台、离线、其他页面接管和换人生均需明示恢复策略；不能先存收益再另存活动进度，也不能靠禁用按钮阻止批量/旧页面绕过。

| 顺序 | 独立实施项 | 该项的玩法与交互验收 |
| --- | --- | --- |
| U2-I | 共享活动机制＋修炼首条闭环 | 确定周期/产出/预算/暂停/目标与恢复合同；开始后连续至少两周期无需再点击，逐次保存、上限停止、设置/查看不打断。只声明修炼适配已完成 |
| U3 | 采集与宗门委托 | 地点/资源目标/预算安排→自动积累→达标停止；确定与替代来源都可理解，不暗中旅行 |
| U4 | 炼丹与炼器 | 配方/成品/保留量→自动炉次或一次铸造→真实成果；与恢复/突破目标连接，材料不足与重复拥有有明确停止 |
| U5 | 功法、法宝与补给 | 研习/配装一次安排、药物阈值、库存补给和保留线；实际效率/战策差异可解释，不无限买卖/收费 |
| U6 | 行旅、遭遇与自动斗法 | 可预设计划与战策，双方真实出招/风险/撤退清楚，受伤/补给/失败可恢复，剑符有实际区别 |
| U7 | 机缘、破境、问心、渡劫与收卷 | 已确认的有限行动可安排完成；未知分支停待决定，真实物品/检查点/因果与两结尾保留，无自动连跳/代选 |
| U8 | 长期节奏与完整玩法复核 | 各境资源/效率/搭配/风险取舍、正常新档及恢复连续可玩；统计干预次数与原因、策略差异、进展与真实试玩意见，不能以速通或等待长短判定完成 |

这是既有功能放置化与逐玩法交互的分期路径，不是一次把所有功能并行重写。每项实施前细化其具体参数/代码范围/验收/回滚，每轮仅完成一项；每三项做当前授权范围的全面检查-debug。页面兼容开发与测试继续暂停，不自动执行跨浏览器、移动、窗口/字号和环境性能矩阵；已知缺口与原门槛保留。

## 每项完成的判定与持续研究

每项必须交付：实际安排入口与有界默认策略；真实周期/限次或已选边界应用过程；预算/耗材/停止原因与完整回执；独有的游戏表现；定向规则/原子保存与固定1440×900 Chromium实走证据。持续或具有可中断执行过程的活动还须有切页后可辨认的状态、暂停/继续/停止及确定的提交边界；即时单次配置提供撤销未提交意图、原子成功/失败和必要的再次调整入口，不为凑暂停/读秒制造假等待。完整策略覆盖仍用25行矩阵逐项登记，“通用调度器已写”不能把所有适配器一并标完成。

验证应包含周期前无收益、连续周期、目标与预算停止、零资源恢复、取消/提交竞态、失败重试/响应丢失、刷新与旧页面回调、换人生隔离。风险需要时使用真实存储与完整Game对照，不能只测按钮文字。长期平衡另验：操作次数是否减少、等待期间有无规划、回访是否有可理解变化、不同策略是否有取舍。自动化加速仅验证规则可达，不能证明挂机节奏或趣味。

持续研究由实际缺口驱动：每个玩法改造前复核相关官方规则或明确局限，记录“来源事实→项目经验→实际改动→结果→未解决反馈”；用户指出仍像软件、凌乱或无趣时重新定位该玩法的决策与反馈，不能以通过测试或更新本文推翻。研究、设计、代码、运行证据、平衡与用户认可始终分开。

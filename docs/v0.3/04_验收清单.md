# 尘缘问道｜Demo 验收清单 v0.3

以下均为待执行的验收项。本文没有宣称测试已通过。

## A. 流程与数值

- [ ] 新玩家不读外部说明也能完成创建角色、首次选择、入道和试炼。
- [ ] 剑修×赠丹、剑修×交易、剑修×离开、符修×赠丹、符修×交易、符修×离开六条核心路线从新档到飞升成功。
- [ ] 没触发随机奇遇、没有任何稀有掉落时仍有完整通关路径。
- [ ] 修为不足或突破物不足时分别展示缺口和实际可达来源；不以剧情完成代替资源成本。
- [ ] 主线身份物不可售；临近突破物默认锁定；可售材料售出后有确定重新获取路线；无背包容量丢失。
- [ ] 零灵石、低气血、没有丹药时仍有恢复和基础资源获取途径。
- [ ] 可重复资源行动可批量处理；逐次与批量结算等价；事件、战斗、物资不足、修为满及目标完成会停止批次。
- [ ] 闭关不等待现实时间；阅读、换页面、关闭网页不消耗寿命。
- [ ] 寿限对正常路径和合理试错留有余量；寿尽能解释原因并提供恢复入口。
- [ ] 两个成功结局都是可达、完整的收束，不把未善待 NPC 当作必败条件。

## B. 战斗与策略

- [ ] 敌方下回合意图准确，实际行动与意图一致或有明确受打断提示。
- [ ] 剑意积累/消费、符印持续/延长/引爆的效果与说明一致。
- [ ] 丹药占行动；无物品/灵力时指令不可执行且原因明确。
- [ ] 同一回合内重复点击只执行一次。
- [ ] 双方濒死、持续伤害击杀、护盾溢出、敌方被打断等边界符合固定结算顺序。
- [ ] 普通战败与渡劫失败都能回到有效准备状态。
- [ ] 战败提示能帮助玩家调整，而不是只显示“战力不足”。
- [ ] 战斗中不能换装或用页面跳转绕开战斗。

## C. 因果与内容

- [ ] 开场三种选择即时代价/收益清楚，后续文本与标记相符。
- [ ] 至少两条主要因果链有起因、中期回响和终局影响。
- [ ] 人物未相识、已相助、疏离的文本不会串线。
- [ ] 所有 36 个事件定义（若缩范围则按批准数量）均通过引用与条件检查。
- [ ] 必需任务和可选准备项在界面上明确区分。
- [ ] 主线不会因随机事件覆盖或不同页面重复进入而消失。
- [ ] 没有 lorem ipsum、测试奖励、错误占位图片或“敬请期待”的空入口。

## D. 界面与美术

- [ ] 视觉保留批准风格：青黛、暖纸、旧金、云海与红叶，而非退化为普通后台表格。
- [ ] 所有动态正文、数值、按钮、进度条是实际网页元素，不烘焙进整张图。
- [ ] 当前地点、事件、境界、法宝槽与底栏高亮一致。
- [ ] 1280×720、1440×900、1920×1080、390×844 下关键操作可见可用。
- [ ] 150% 字号下正文不截断、关键选项不被底栏遮挡。
- [ ] 桌面键盘焦点清晰，手机无需悬停也能了解禁用原因和代价。
- [ ] 正文对比度满足目标；状态不只用颜色表示。
- [ ] 文本首屏完整出现，逐字效果可关；长事件自动降低图景占比。
- [ ] 动效和音乐可关闭，跳过突破/飞升动画不改变结算。
- [ ] 三种常见状态都有可理解表现：暂无线索、条件不足、存档失败。

## E. 存档与数据完整性

- [ ] 事件已显示但未选时刷新，仍是同一个事件与选择上下文。
- [ ] 选择提交后刷新，不重复扣成本或发奖励。
- [ ] 战斗中每个已提交回合可恢复，意图、状态和 RNG 不重抽。
- [ ] 渡劫前检查点包含装备、背包、关系和完整任务状态。
- [ ] 保存失败不出现“已保存”；无半次事务状态。
- [ ] 导入坏 JSON、未知新版本、负数资源、不存在的 ID 时，旧档仍保留。
- [ ] 旧版本只经已测试迁移函数导入。
- [ ] 两标签页并发时拒绝过期 revision，不静默覆盖新进度。
- [ ] 用户导出—清理站点数据—重新导入后，关键状态一致。
- [ ] 保存提示明确说明本地数据的边界，不能把本地档称为云档。

## F. 性能与部署

- [ ] 在记录的固定条件下测首屏；建议冷缓存、10Mbps/150ms、注明设备与 CPU 限速，首次可行动目标 ≤3 秒。
- [ ] 首屏关键资源预算 ≤2.5MB，其余按需载入，全包资源目标 ≤15MB；不达标时先分析而非隐瞒。
- [ ] 图片加载失败仍能阅读与继续操作，关键按钮不依赖背景图加载完成。
- [ ] 生产构建可在静态服务运行；页面刷新路径与资源 base 配置正确。
- [ ] 目标浏览器测试 Chromium、Firefox、WebKit/实际 Safari；自动化模拟与真实移动端检查分开记录。
- [ ] 无未处理异常、控制台阻断错误或未记录的外部关键请求。
- [ ] 依赖锁定、版本记录、素材来源与许可记录随发行包交付。

## G. 真人试玩（探索性目标）

建议首轮约 10 名目标玩家，不同时在场逐步教他们操作。未另行说明前，不上传个人信息，试玩记录由本人知情导出。

- [ ] 以至少 8/10 不靠场外讲解理解短期目标并完成一次主动资源/搭配调整为探索性目标，不要求首次突破。
- [ ] 约 30 分钟观察玩家是否知道下一目标、能定位短缺物来源、能解释一次资源取舍；不要求达到指定境界或通关，不惩罚慢读。
- [ ] 至少 7/10 能具体解释一次由行动或搭配改变的战斗结果。
- [ ] 在实际到达相关内容的玩家中观察因果回响是否可辨；不能因未在 30 分钟到后期就判定失败。
- [ ] 分别记录主动继续原存档、探索另一准备路线和自愿新开角色；不只追踪短时重开。
- [ ] 记录退出节点、卡住原因、重复点击行为和读取提示的情况。

上列比例是内部目标，不是已达到的指标，也不是市场成功的统计证明。

## H. 8 分钟演示

- [ ] 从正常新档展示开场；之后跳转节点明确标为演示存档。
- [ ] 演示存档来自同一版本的合法指令回放，不手填不可能状态。
- [ ] 可依次展示视觉、选择、战斗策略、因果回响、突破/飞升、生平。
- [ ] 演示不需要后台加灵石、修改境界或跳过未实现系统。
- [ ] 演示前后不覆盖正常玩家自动档。
- [ ] 最终候选版本完整脚本连续复现通过，并记录版本与失败情况。

## 放行与止损

流程阻断、奖励重复、存档损坏为阻断级问题，未修复不进入对外演示。局部装饰瑕疵可以记录为已知问题，但不能用“只是 Demo”豁免流程和数据问题。

若 M1 不好玩，先检查资源取舍、反馈与战斗，不能只提高突破赠品或拉长刷取；若 M2 走不通，暂停新支线；若 M4 阅读吃力，先缩图景和装饰，不缩正文；若 M5 缺乏继续成长兴趣，先分析目标清晰度、物品用途、路线差异与因果，不增加签到或无意义等待。

## I. v0.3 成长、经济与长存档专项

- [ ] 改变现实会话时间或阅读停留时间，不改变修炼收益、价格、掉落、解锁和突破结果。
- [ ] 没有五分钟筑基、四十五分钟飞升等隐含保底；完整飞升仍经真实规则可达。
- [ ] 修为达标但没有突破物不能突破；物品足够但修为不足也不能突破。
- [ ] 满足条件后，突破消费与境界更新原子完成，重试不双扣；正常突破不随机失败。
- [ ] 每个当前境界所需的下一次突破物在本境至少有确定主来源和可达替代路线，无境界循环依赖。
- [ ] 随机奇遇与额外掉落全部关闭时，稳定资源循环仍支持成长。
- [ ] 所有投放物品都有实际用途与消耗/留存政策；同材料用于治疗、加速或突破的取舍可见。
- [ ] 每条准备路线核算材料、货币、修为、游戏耗时、治疗与失败成本，不只比较毛收益。
- [ ] 检查无行动成本的买卖—炼制—出售循环；无凭空净增资源。
- [ ] 低阶刷取不绕过高级物品取得条件；仍有部分基础材料的后续用途。
- [ ] 安全采集、修炼优先、战斗优先、购买优先四类策略分别回放；差异为行动数与风险预算，不是按分钟强制拉齐。
- [ ] 单次固定脚本可通关不作为全面平衡证明；记录失败、净消耗、溢出、材料囤积和恢复路径。
- [ ] 中途退出后继续原档能显示明确下一目标；保底来源进度、一次性领取状态和配方版本恢复一致。
- [ ] 改动阈值、来源效率、物价或加成后重跑相关路线；balanceVersion 与报告一致。

数值初值与敏感性分析仅用于发现风险；真实理解、愉悦与持续游玩仍需观察，不用脚本行动次数替代真人体验。

# 相似竞品研究：少做系统，多做相互作用

日期：2026-10-13。分类和机制证据见[来源目录](sources.md)。本章F为已查证产品说明，I为我们的设计判断，H为待测假设。不是亲玩评测或市场规模报告。

## 1. 选择这些参照的原因

## 2. 逐项结论

### 2.1 想不想修真：玩家先理解“下一关”，再理解所有物品

F：官方介绍把修炼、门派、丹器和寻宝放在同一成长想象中，而非独立无关的小游戏。[S01](sources.md#s01)

I：我们的角色栏应回答“下一境界缺什么”。由缺口反查来源，比四处寻找按钮更适合文字页面。不是复制它的具体界面或数值。

实施：目标卡只追踪一个主要目标；缺少筑基丹时展开“炼制/购买”两种准备；材料项提供来源、所需境界、行动消耗和返回目标入口。门派不再另设声望/贡献币。

H：首次玩家无需外部攻略，能从目标卡找到下一步。以观察任务验证，不使用竞品评分代替证据。

### 2.2 修仙立志传：新鲜感不必等于新系统

F：商店介绍强调境界推进后增加生活技艺、宗门经营等层次。[S02](sources.md#s02)

I：这种扩展展示成长空间，但对有限Demo，照搬会使每阶段都需要新界面、资源和教程。我们把新鲜感放在同一规则的变化：筑基有第二组术法，金丹有法宝，元婴见旧缘，化神把已有准备汇集到渡劫。

实施：内容预算固定；原有材料继续有用途，每境界新增一种关键材料即可。突破后展示一条能力变化与一个可行动目标，不发十个任务。

H：不增加系统入口，也能让玩家感到境界有区别。试玩分别询问“刚才变强在哪里”和“接下来想做什么”。

### 2.3 觅长生：时间是资源，不是现实等待

F：开发者说明修炼、学习与悟道消耗世界内时间，功法、神通、法宝等共同影响战斗。[S03](sources.md#s03)

I：适合本项目的是准备之间的机会成本。灵石买丹、辅助修炼、学术法不能总有一个绝对最好；战斗胜负则应能解释到行动顺序，不只归结战力。

实施：所有行动写明游戏年月与物品成本；战前显示敌方机制；境界与丹药双条件突破。阅读、设置和离线不耗时。不借残酷永久损失来延长演示。

H：稳妥取材与高风险战斗都有合理玩家，玩家能复述一次“为什么没立即释放技能”。

### 2.4 一念逍遥：专属资源需要行为辨识度

F：官方儒修说明呈现“文气积累→达到条件→获得额外效果/释放神通”的机制，材料来自2025公告而非2026全版本审计。[S04](sources.md#s04)

I：不是再做儒修，而是让剑意与符印有不同归属、持续方式和操作理由。

实施：剑意显示在玩家侧，积攒后破势；符印显示在敌方侧，逐回合灼伤并可提前收割。两者分别有清楚的剩余层数或持续回合、消耗预览、触发文字。

H：不看技能名称，玩家仍能分辨两个流派。通过固定敌人的对照操作验证。

### 2.5 Melvor Idle：每项投入必须回到核心循环

F：官方介绍明确强调不同技能彼此服务，生产积累会支持其他技能与战斗。[S05](sources.md#s05)

I：我们的规模应更小，但物品的用途链不能更弱。草药既可救急，也可留作突破；法宝投入降低战损，但不能无条件加快一切。

实施：物品详情展示“用于什么/从哪里来”；固定配方复用材料；批量执行到目标缺口为止；安全动作可以汇总结算，事件与战斗必须停止等待玩家决定。

H：材料不再只是库存数字，玩家能解释保留而非出售的理由。避免用新职业进度条填补现有经济的空洞。

### 2.6 A Dark Room：先给情境，再给管理面板

F：开发者对Steam版描述有限互动逐步展开；浏览器源码亦可见资源制作和现实冷却，两个版本不能逐项等同。[S06](sources.md#s06) [S07](sources.md#s07)

I：我们只采用渐进揭示。第一屏让玩家遇到一个人、一枚丹和一个决定，之后通过真实操作理解行囊、修炼和目标，而不是安排30分钟教学播放器。

实施：开场仍可立即看存档设置；未学习系统收在简短说明里；有用途时再展开配方和构筑。随时可查看规则，不故意隐藏必要信息制造难度。

H：首次玩家不会被四页几十个按钮淹没；熟悉玩家也不被强制教程拦住。

## 3. 收敛出的产品定位

**玩家经营的是一个修士的准备与选择，不是一个放置工厂，也不是一个自动演化的世界。**

核心体验：一个可追踪的目标、一组有成本的筹备方式、一次能理解的挑战、一个属于自己的回响。持续游玩依靠“我知道下一步想得到什么”，而不是固定时长通关或每日登录压力。

| 决策ID | 本轮优化 | 影响的现有部分 | 成本边界 |
| --- | --- | --- | --- |
| D01 | 行为触发引导 | 开场/目标卡 | 不建独立教程引擎 |
| D02 | 目标→缺口→来源→返回 | 当前目标/物品详情 | 不做自动最优路线求解器 |
| D03 | 稳妥/冒险/采购三种筹备 | 来源/战斗/商店 | 共用物品，不新增职业货币 |
| D04 | 2修法内的真实换装 | 12功法/4法宝 | 不增五行、随机词缀或天赋树 |
| D05 | 有条件的因果回响 | 现有NPC事件 | 条件配置，不引入LLM |
| D06 | 行前准备—遭遇—归来 | 历练页 | 不建自由地图或多层副本系统 |
| D07 | 原子操作与可重复恢复 | IndexedDB | 不加账号云存档 |
| D08 | 阅读优先的古风表现 | 已认可主界面 | 4母版、5头像、复用组件 |
| D09 | 全流程与体验分开验收 | G5 | 不用测试条数冒充趣味结论 |

所有H假设的验证见[验收文档](06-validation.md)。资料调研足以提出这些改动，但不能证明它们已经带来更高留存。

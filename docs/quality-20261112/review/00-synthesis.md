# 《尘缘问道》质量评审综合结论（三份评审合并）

> 2026-11-12 · 协调者综合。三份原始报告：`review/01-player-experience.md`（实机试玩）、`review/02-game-design.md`（玩法数值）、`review/03-engineering.md`（工程）。试玩截图在 `review/ux-shots/`。
> 评审全程未修改任何受 Git 跟踪的文件。

## 一句话总论

**规则引擎是干净且可通关的，但包在它外面的三层壳都出了问题：玩法层是"开着页面读秒"而不是放置游戏（无离线收益、斗法碾压主循环、寿元空转）；界面层是"带国风皮肤的存档管理台"（工程文案、四层导航、关键时刻零反馈）；工程层是"证据簿记机器"（65% 的提交在维护测试与守卫、字节帽把源码压成单行、一次目录删除打红全部 CI）。三层各有清晰的根因，也都有可执行的修法。**

## 三层诊断

### 1. 玩法层：为什么"不好玩"（02 号报告，全部数值由实跑 160 条路线的规则引擎得出）

| 根因 | 事实 | 后果 |
| --- | --- | --- |
| 无离线收益 | 每个周期必须在页面内走满 30–240 秒；关页零收益。通关要页面打开累计 4.5–7.7 小时，其中 63–83% 是纯吐纳读秒 | 与放置品类核心契约相反，是流失第一原因 |
| 斗法碾压主循环 | 化神打守灵 333 修为/分（吐纳只有 175），还 +83 石/分、掉渡劫材料；满血无药默认战策 100% 胜率 | 最优策略是"一路打架"，采集/委托/炼丹全部沦为次优 |
| 寿元空转 | 全程只用 224–371 游戏月，到化神期不足可用寿元 2%；所有"月"成本和余寿保留线是装饰 | 最有戏剧性的资源完全没有戏剧 |
| 经济被支配 | 6 个委托全部劣于同境自采；购丹路线（5.66h）快过自采（6.01h）和委托（6.47h）；金丹丹自炼 400 比直购 380 还贵 | 一半来源是无效选项，"筹备取舍"只有一个答案 |
| 零重玩 | 36 个事件全一次性，无传承/随机/终局，结余灵石无处可花 | 第一遍看完 100% 内容 |

### 2. 界面层：为什么"像工作台"（01 号报告，实机试玩 + 截图）

- **关键时刻零反馈（最严重）**：抉择、每轮收获、突破、战斗胜利、飞升结局全部没有回响；玩家得到的最高礼遇是一行 14px"本段已保存 +2"。飞升结局只有一行小字。
- **工程语言文案**：「已保存本次明确安排的一次行动，未自动接续其他活动」「替换暂停安排·服用回春丹」「原子提交后逐次记载」——每点一个按钮先读一段免责协议。
- **操作路径过长**：一次 NPC 对话 9 步（选项还要翻页）、吃一枚丹 7 步。
- **放置感弱**：默认授权 5 轮/1 场就停，运行画面静态（打坐 15s 与 30s 无差别）。
- **导航深且重复**：斗法 4 级、每屏 23–32 个控件、未解锁内容（法宝/剑简/坊市）从第一分钟全开。另有 8 个明确 bug（双返回按钮、行旅中标题未更新等，均附截图）。
- **好的部分应保持**：单张美术已达"像游戏"水准；目标面板的"目标→缺口→来源"链路是正面案例；保存失败态是全局做得最好的界面。

### 3. 工程层：为什么"改不动"（03 号报告）

- **goal-4 删除事故（已推送）**：本地测试 162 失败（156 个由删除造成），远端 CI 16/16 全红。守卫在运行时读取 goal-4 下的基线文件——删目录等于删测试输入。
- **守卫保护的是字节不是玩法**：139 个源文件被整文件 sha256 钉死、68 条逆变换链、161 例台账测试（占根套件 21%）；592 个提交中 65% 在改测试和守卫。无 `.gitattributes`，CRLF 检出下哈希全灭。
- **字节帽把源码逼成压缩体**：App.vue 单行 3,302 字符、stage-r4.css 整个文件一行 8,804 字符，无法 diff/review。
- **"界面凌乱"的结构性根因**：828 个 `!important`、1,019 个 `#app` 选择器、0 处 `@layer`；2,274 个不同颜色（88% 只用一次）、86 个字号；App.vue 160 KB 承担 8 类职责。每轮 UI 迭代都手挑略不同的颜色，这是机械成因。
- **健康面（应保留）**：规则/界面边界干净（`src/` 零 DOM 引用）、写协议严密（CAS 单事务、丢回复重放正确）、存档导入校验严格、XSS 面 0 命中、双 `npm audit` 0 漏洞、引擎行为测试真实有效。

## 合并后的优先级清单（跨报告去重）

### P0 — 决定"能不能留住玩家"（建议最先做）

1. **离线收益/到期合同**：按 wall-clock（dueAt 已存在）结算关页期间的活动，设追赶上限，回来给汇总。工作量：大。风险：原子事务与多页面接管边界需扩展，数值结构变化需重跑 160 矩阵。
2. **关键时刻补结果反馈**：抉择回响、轮次收获跳字、突破定格、战斗胜利定格、成丹出炉、结局画卷——内容就是真实结果数据，不加奖励。工作量：中。
3. **斗法数值归位**：普通敌人修为掉落大幅下调或移除，战斗回报归材料/灵石/风险内容。工作量：小（改数值）+ 回归。
4. **寿元变成真资源**：各境寿限压到正常路线的 1.5–2.5 倍，让"月"稀缺、委托的月成本、寿尽结局都真实生效。工作量：小（数值）+ 回归。
5. **界面文案去工程化**：动词世界化（赠丹、启程、开炉、迎战），"回执/授权/原子提交/快照/runId"建立映射层全量替换，协议语言收进帮助与详情。两份报告独立得出同一结论。工作量：小–中，风险极低。

### P1 — 快赢与体验修复

6. **修 8 个明确 UI bug**（双返回按钮、行旅中标题、过期门槛标签、导航高亮、斗法"每轮30秒"、名牌压图、游戏月+1、服丹冲突文案）。小。
7. **默认授权改为"持续到目标/手动停"**，限额做成进阶选项。小–中。
8. **经济三线重调**：委托双产出不劣于自采、突破丹直购溢价 1.3–1.6 倍、自采+炼制成为确定优势路线。中。
9. **操作路径压缩**：选项并排、点选即一次确认；消耗品在行囊一键使用；"等 6 秒"只留真正重大抉择。中。
10. **导航瘦身**：读秒/暂停各留一处、页头按钮收进菜单、未解锁入口按境界置灰写明条件、消灭"1/1 页"无效分页器。小–中。
11. **工程止血**：恢复仍被运行时读取的少数 goal-4 文件并迁入 fixtures；加 `.gitattributes` 统一 LF；修 4 个跨平台 bug。CI 由全红变可绿。小–中。

### P2 — 结构性改革（P0/P1 落地后再排）

12. **CSS 收敛**：全部全局 CSS 包进显式 `@layer`（零视觉变化）、禁新 `!important`/`#app`、2,274 个颜色收敛到 ~12 个 token。中。
13. **拆 App.vue**：先抽里程碑对话框组与四个 tab 内容组件，逐 seam 降到 ~30 KB。大。
14. **守卫机制归档**：台账/逆变换/整文件钉 → 行为断言 + Git 历史基线；同步删死代码（不可达的 `store.act`/`execute()` 路径、死 CSS 类、`CultivationPanel.vue`）。大，迭代提速一个数量级。
15. **回执/备份滚动裁剪**（receipts 无界增长 + 历史全扫分页，长期退化点）。中。
16. **构筑与战斗深度**：功法升级互斥分支、法宝换装成本、符修渡劫补正、敌人机制差异化。大。
17. **终局与重玩**："此生账本"回顾、NG+ 传承、事件池随机化。中–大。
18. **文档减肥**：AGENTS.md 两段式（常青规则 + 当前状态）、README 日报归档、修 113 处死链。中。
19. **新手 30 分钟**：引导性首战 + 第一笔委托经济环前置。小–中。
20. **仓库体积**：`art/` 233 MB PNG 入 Git（`.git` 530 MB），建议 Git LFS。小。

## 建议的执行顺序

1. **先止血（1 天内）**：P1-11 工程三项（goal-4 断链、.gitattributes、跨平台 bug）——CI 不绿，后面什么都验不了。
2. **第一批快赢（每项独立可验）**：P1-6 八个 bug → P0-5 文案映射 → P1-7 默认授权 → P1-9 操作路径 → P1-10 导航瘦身。这批不改数值、风险低，直接回应"界面凌乱/像工作台"。
3. **数值三件套（一起改、一起跑 160 矩阵回归）**：P0-3 斗法归位 + P0-4 寿元 + P1-8 经济三线。
4. **核心系统**：P0-1 离线收益（最大单项）+ P0-2 结果反馈六件套。离线收益落地后，反馈密度问题自然缓解一半。
5. **结构改造穿插进行**：P2-12 CSS @layer 可在任何 UI 改动前先做（零视觉变化）；P2-13/P2-14 按迭代节奏排。

## 注意事项（各报告自己声明的边界）

- 玩法报告的数值建议都没跑 160 路线回归；斗法刷修为总时长是分段估算；无真人试玩数据，"好不好玩"来自机制推导。
- 试玩报告的计时全部用虚拟时钟快进，真实挂机节奏未评价；筑基后内容（照影古境、法宝认主）只看了锁定页。
- 工程报告的守卫归档建议需要先补关键行为断言再拆；`vite build` 与全部 Playwright 套件未跑。
- 项目 AGENTS.md 里的合同体系与这些建议有冲突处（如"不凭经过的时间伪造收益"与离线收益），落地前需要明确修订哪些合同条款。

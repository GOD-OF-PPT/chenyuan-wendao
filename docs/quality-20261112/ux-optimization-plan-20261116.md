## 1. 问题诊断

**结构性根因一句话**：三条准则被字面化后产生反效果——**「不许滚动」→ 每页一条；「一个主要决定」→ 一次只显示一件；「成本/条件/读秒/失败/暂停常驻」→ 同屏重复 2–3 处**。再加全局 CSS 无约束，局部清理会被覆写。P0 必须在不违反现行条款的前提下先切断这条链。

## 2. 优化目标

全部为**呈现层可观测指标**，只在 1440×900 / 单 Chromium 下度量；**不含任何数值平衡指标**。

| 指标 | 现状 | 目标 | 度量方式 |
|---|---|---|---|
| 顶栏可见信息组 | ≈9 | ≤6 | 截图 + DOM 计数 |
| 每屏可见控件 | 23–32（旧评审实测，需 T00 复核） | ≤12 | 逐屏截图核对 |
| 每屏正文密度 | 220–430 字（旧评审实测） | ≤180 字 | 文案计数 |
| `pageSlice(...,1)` 一次一件 | 5 处 | 0 | 静态 grep + 目录项同屏断言 |
| 同类状态信息副本 | 2–3 处 | 1 个权威常驻点 | DOM 文本去重断言 |
| 语义不明/工程动词按钮 | 有残留 | 0 | 全仓可见文案扫描 |
| 结果态「结果 + 下一步」 | Q11 已建，需复核可感知性 | 100% 且动效后仍可见 | 浏览器断言 + 连续刷新 3 次 |
| 吃丹 / NPC 呈现点击 | 7 / 9 步（旧版） | ≤4 步（只合并纯展示步骤） | 点击路径记录 |
| 字号取值 | 86 种 | 3 档（18 / ≥14 / ≥44） | CSS 静态断言（P2） |

**约束**：以上全部通过布局、文案、导航、引导、反馈、展示口径达成。**不得**通过改境界数值、掉落、时钟、默认值本身、停止条件本身来实现；「默认值/成本/停止条件」只允许改**折叠方式、命名与说明文字**。

## 3. 具体优化方案（T00–T18）

> **通用红线（每项适用）**：不改 `src/full/*-current.ts` / `content.ts` / `goals.ts` 结构；界面只**读取** `costsForAction()` / `requirementsForAction()` / `previewAction()` / `goals.ts` 既有返回值并重新组织，**不在组件重算费用、门槛、奖励，不新增求和/换算/推算**；不动写入核 `commandId/runId/expectedRevision`、活动 CAS、原子持久化、虚拟时钟、`Game` schema；不新增内嵌滚动容器；不用 `eval`；不提交秘密/玩家档/字体；单项可独立 revert。
> **每项均写明「对易用性 / 对玩家体验的作用」**（见各条末两行）。

### P0 · 低风险快赢（不动数值，直接回应「凌乱」）

**T00 当前 main 实机复核（前置，先于所有改动）**
- 做法：按 `web/README.md` 启动当前构建预览，用固定 1440×900 单 Chromium 走一遍「欢迎→开场→洞府→目标来源→活动→战斗→行囊→生平→帮助」，逐屏截图存独立目录；产出「旧评审 7 类问题 × 当前状态」对照表，并把 `ux-shots/` 旧图标注为历史证据。
- 作用：**易用性**——避免在已修问题上重复劳动、避免误判优先级；**体验**——把「用户当前感受」与「旧版截图」对齐，保证后续改动打在真实痛点上。
- 验收：对照表覆盖 7 类 S1–S7 + 8 bug；每屏有当前版截图；`docs/quality-20261112/delivery-status.md` 记「计划/复核」状态。门禁 G0（只读，不改代码）。

**T01 顶栏三段式减负**
- 现状：`GameHud.vue:36-109`。做法：左「人物 + 资源四数（只读既有 `store` 值）」／中「一句话当前活动 + 当前目标（≥44px）」／右「帮助、设置 + 一个『本段』入口」；存档状态收成角标；右下「数值未平衡」移入「设置→关于」。文案示例：「正在雾隐妖狼历练，这一段走完会自动回来」（只搬运既有展示值，不做算术）。
- 作用：**易用性**——视线从扫 9 组降到读 1 句状态 + 1 个目标；**体验**——顶栏不再像后台仪表盘，洞府美术成为主角，放置感靠「会自动回来」传达。
- 验收：顶栏可见控件 ≤6、目标字号 ≥44、辅助 ≥14、无文字重叠；`[data-hud] button` ≤6；顶栏无 `overflow:auto`。门禁 G0。风险：仅 `GameHud.vue` 模板 + `shell.css` 顶栏段，不动 `App.vue` 状态中枢。

**T02 战斗浮层与名牌定位**
- 现状：`06-battle-overlap.png`。做法：读秒环移到右上安全区、名牌移到立绘下方独立行；`art03-equipment.css:135` 的 `max-height:100px` 裁切改为「整行 + 展开查看」（用既有抽屉，不新增第二条滚动条）。
- 作用：**易用性**——读秒、名牌、敌人意图可同时读到；**体验**——单张战斗美术完整保留，信息浮在画外而非压在画上。
- 验收：浮层 bounding-box 与立绘主体交叠 =0；名牌不压图；旧 `max-height:100px` 消失。门禁 G0。风险：仅定位 CSS，不改读秒数值、不改时钟/活动 generation。

**T03 单一权威常驻点去重**
- 现状：战斗同屏顶栏状态 + 右栏战策 + 右下工程长段 + 读秒环，同类信息 2–3 份。做法：为 5 类信息各定一个权威点并写进 `GameHud.vue` 注释对照表——读秒→`TrainingActivity.vue`；成本/条件→`ChoiceCard.vue`；暂停/失败→`StatusSurfaces.vue` 横幅（全局最佳界面样板）；活动状态→顶栏一句话；当前目标→顶栏 ≥44px。其余位置只放入口，**只删副本、不删任一常驻点**（这正是现行「常驻」的字面要求）。
- 作用：**易用性**——同一数字只出现一次，不必核对哪处最新；**体验**——战斗回到「一张画 + 一个读秒 + 一个结果」。
- 验收：5 类关键文本同屏出现次数 =1；暂停/失败态 `StatusSurfaces` 仍常驻。门禁 G0。风险：不动计时逻辑、不动失败态保存。

**T04 「一次一件」分页整改（修正旧方案：不是删 1/1 分页器，而是提容量）**
- 现状：`FateCatalogue.vue:143-144`、`LifeCatalogue.vue:71`、`GoalPanel.vue:152`、`LearningPlanner.vue:120`、`NarrativePanel.vue:80` 的 `pageSlice(..., 1)`。做法：在 1440×900 内把每页容量提到该容器可容纳的条数（人物名帖并排、生平卷轴连续列、需求/来源同屏并列、对话选项并排），**不新增滚动容器**；`CataloguePager.vue` 的 `v-if="pages > 1"` 保护保留。文案示例：「1/6 页 共 6 项」→「共 6 段见闻」。
- 作用：**易用性**——消灭「点 6 次看 6 行」，做决定时一次看全；**体验**——卷轴/名帖美术被真正用起来，而不是当分页框。
- 验收：五处 `pageSlice(...,1)` 清零；卷轴 6 项同屏可见、无「1/N 页」、无内嵌滚动。`pageSlice` 算法本身不改、数据源不改。门禁 G0。

**T05 去工程化第二批（欢迎页 / 帮助 / 引导正文）**
- 现状：`App.vue:1019`、`GameplayHelp.vue:45,47`、`guidance.ts:15,50,60`。做法：把协议长句拆为「一句主文案 + 可展开的细则」，细则保留 0152 允许的必要技术说明但默认收起；主文案用玩家动词。示例：欢迎页「安排修炼，积累材料，筹备下一步。数值未平衡；游戏月在…」→「**在洞府潜修，攒下第一笔材料。**」＋展开「关于时序与存档」；帮助长段拆成 4 条短句；`0152` 映射继续对齐（战报/收获明细/行程记录、本次限额/用药上限/下一次选择）。
- 作用：**易用性**——点按钮前不再先读一段免责协议；**体验**——界面从「软件日志」回到「修仙行程手记」，题材一致。
- 验收：可见文案中 `commandId|runId|revision|CAS|原子提交|快照` 命中 0（代码标识符不算）；首屏协议长句 ≤2 行；细则可展开且内容不丢失。门禁 G1（改文档引用时补 `check-doc-links.py`）。风险：只改标签/文案，不动 receipts 真源、不隐藏失败/待核对状态（0152:7 红线）。

**T06 导航与返回一致性复核（旧「双按钮」已修，改为当前态核对）**
- 做法：T00 复核后，统一返回语义为「回到方才」，确认 `use-stage-navigation.ts` 高亮由当前 `tab/hubView` 唯一派生、`[data-nav-active]` 唯一；核对行旅中副标题随既有活动状态更新、`GoalPanel.vue` 门槛标签不再对已达成境界显示过期条件。
- 作用：**易用性**——一处返回、一个高亮、标题随行程走；**体验**——目标链路不再被同义按钮打断（正面项保持）。
- 验收：返回入口 =1、高亮项 =1、副标题与顶栏状态一致。门禁 G0。风险：不改 tab/hubView 枚举、不改 `navigationGate` 判定。

**T07 结果反馈「可感知性」复核与常驻结果强化（Q11 已建，不重做）**

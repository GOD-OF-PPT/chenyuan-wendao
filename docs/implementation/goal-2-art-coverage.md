## 本轮实施

用户进一步明确“整体交互不像游戏界面，交互效果反馈不足，游戏流程不完善”，逐字见 goal-2/amendments/2026-10-20-gamefeel-feedback-flow.md。本条优先：三幅绘画必须服务实际操作，本轮同时补游戏状态与持续结果反馈，不把加插画算作交互完成。

1. 使用内置imagegen制作三份无字透明主题绘画：行囊与灵材、丹鼎与丹药、功法与法宝意境。它们是页面装饰，不能暗示已拥有未持有物品；实际14物资/7配方/12功法/4法宝仍由真实Game与共享查询展示。简单UI符号/按钮继续DOM/SVG，不栅格化原40符号。
2. 三图进入仓库原稿、逐图提示词/工具回执/hash/实际像素/alpha及确定性运行导出。源图不覆盖旧文件；运行图≤120KB/张、合计≤360KB，不放大，不预加载其他功能图。独立目录美术清单；原全部预算不提高、不搬出旧代码。
3. 物资/丹炉、功法/法宝、筹备页形成图像主题区+真实信息/操作区的单屏游戏构图。文字、成本、缺口、操作/只读、分页/返回保持；按实际动作显示读秒并原子保存，插画不参与结算。长文本完整、无缩字/裁切。已有默认560基础布局保持，全部兼容仍最后T08。
4. 新增统一功能覆盖清单，列出全部核心流程/状态的代码入口、实际验证与缺口责任。保存PR44原始结果；下一项T07M先补完整当前功能/状态矩阵与综合作业接线，再进入最低优先级T08。完整结果分清已执行通过、实际失败、未执行，不能只交“待T09”的空格或把少量路线叫完整。
5. 常用桌面功能页保留人物状态与当前下一步，使用游戏中的状态侧栏与操作舞台，避免切换后丢失身份/成长上下文。主舞台及功能页增加持续可读的行动结果：真实行动中读秒/存储中/保存后结果/失败分别呈现，保存后清楚显示实际变化和下一步入口。入口仅查看/定位，不隐藏执行旅行或消耗；保存失败无成功、旧回执/刷新/重放不演新奖励，下一次行动会替换结果。复用共享nextStep与原Store结果，不复制成长规则。

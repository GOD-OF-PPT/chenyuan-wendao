## 已落地行为

- 主舞台按真实状态显示下一步：选择修法、继续修炼、筹备突破物、疗养或确认突破。修为圆满缺丹时，主按钮打开筹备；不再把继续吐纳或不可执行突破当作唯一前路。
- 筹备显示完整配方、实际库存和灵石缺口，自行炼制/坊市成丹可切换。每项材料都能查看共享查询给出的稳定、采购、战斗或机缘来源；缺钱可转委托。前往只旅行/定位，采集、购买、炼制和突破分别确认。按目标取材采用原planCollection，不重复索取已齐物资。
- 历练分地点、采集/委托、挑战、坊市；行囊分物品类别，丹炉/功法/法宝/目标来源采用有限卡片和翻页。6地点、16来源、6普通敌人、14物品、7配方、12功法、4法宝全部可达。常用桌面及560×718默认字号下，当前动作、翻页、返回和主导航不依赖滚动。
- 保留功法完整描述、成本、禁用原因、未来境界目录、配装汇总和旧剑简；目标可编辑并逐层返回。完整指引改为明确的帮助入口打开，可展开/跳过/重看，不挤占目录决策区。新流程复用青黛墨绿及已有山水/人物画作，全部文字和按钮仍是DOM。
- 25类Game动作采用0.6—2.4秒短耗时，战斗0.7—1.1秒，新建/导入/恢复等约0.6秒。执行中显示动作名、总耗时、小数秒倒计时与进度；批量按整批计时。查看、翻页、查看来源不等待，也不增加游戏月。
- 独立单调时钟只负责等待；到期后才调用原Store操作与FullSaveRepository。原commandId/runId/expectedRevision、CAS、回执幂等和原子提交保持，事务complete后才显示成功/播放效果。明确区分“行动中”和“保存中”；读秒前刷新无写入，不补离线收益。失败同意图重试只结算一次，另一页更新使旧命令过期，降低动效仍保留读秒。
